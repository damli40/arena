# vault-a design notes

## What it does, in one paragraph
The vault holds one NEP-141 token. The owner writes a list of trusted payees and approves
invoices (who gets paid, how much, until when). The agent can only say "pay invoice X". The
vault then checks every rule, marks the invoice as "in flight", sends the tokens with
`ft_transfer`, and a callback records whether the transfer worked.

## Invoice state machine
```
            approve_invoice
                  |
                  v
   cancel    +----------+   pay (all checks pass)   +---------+  callback: success  +------+
 <---------- | Approved | ------------------------> | Pending | ------------------> | Paid |
 Cancelled   +----------+ <------------------------ +---------+                     +------+
                           callback: transfer failed
```
- `Paid` and `Cancelled` are final. An invoice id can never be reused, even after it is final.
- "Expired" and "PayeeRemoved" are not stored states. The invoice stays `Approved` in storage,
  but `pay` refuses it and `get_invoice` reports it as `Expired` / `PayeeRemoved`.
- Expiry: payable only while `block_timestamp < expires_at_ns`. At or after the expiry it is dead.

## How the async callback is handled
NEAR cross-contract calls finish in a later block, so another `pay` can arrive in between.
- `pay` flips the invoice to `Pending` and counts the amount against today's cap **before**
  the transfer is sent. A second `pay` on the same invoice is refused while it is `Pending`.
  This is what makes "exactly one transfer per invoice" hold.
- Callback, success: `Pending -> Paid`. The amount stays counted for the day.
- Callback, failure (token panicked: receiver not registered, vault balance too low, etc.):
  `Pending -> Approved` and the day's counter is reduced by the amount, but only if the
  counter still refers to the day the amount was counted against. If midnight passed in
  between, the old day is gone and nothing is subtracted from the new day.
- Success is judged by the receipt outcome only. NEP-141 `ft_transfer` returns nothing and
  panics on any failure, so "receipt succeeded" means "tokens moved".
- The callback is `#[private]` (only the vault can call it) and written not to panic.
- `pay` refuses to start unless at least 45 TGas remain (20 for `ft_transfer`, 15 for the
  callback, 10 for itself). If the callback ever ran out of gas, the invoice would be stuck
  `Pending` forever, which is why this check comes before any state change.

## Daily cap
- The day is the UTC day: `block_timestamp / 86_400_000_000_000`.
- "Spent today" = settled payments + payments in flight. In-flight money counts, so two
  quick `pay` calls cannot both slip under the cap.
- `set_daily_cap` takes effect immediately. Lowering it below today's spend blocks further
  payments today; it does not undo anything.

## Other decisions the spec left open
- **Removing a payee kills its existing invoices for good.** Each payee gets a generation
  number when added. Invoices remember it. Remove and re-add gives a new number, so old
  invoices stay unpayable. Reason: "removed payees authorise nothing" should not quietly
  come back to life on re-add.
- **Payee status is checked at pay time**, not only at approval.
- **Owner and agent must be different accounts**, at init and on `set_agent`.
- **Owner methods that widen what can be paid need exactly 1 yoctoNEAR attached**
  (`add_payee`, `approve_invoice`, `set_agent`, `set_daily_cap`). That forces a full-access
  key, so a leaked function-call key cannot add payees or raise the cap. The protective
  methods (`cancel_invoice`, `remove_payee`) need no deposit, so they are easy in an emergency.
- **`cancel_invoice` on a `Pending` invoice is refused.** The transfer already left and
  cannot be recalled. If it fails, the invoice returns to `Approved` and can be cancelled then.
- **`pay` takes no deposit.** The vault pays the 1 yoctoNEAR for `ft_transfer` from its own
  NEAR balance. The agent can use a function-call key.
- **Init is `#[private]`**: only the vault account itself can initialise it, so nobody can
  initialise a freshly deployed vault with themselves as owner.
- **No `ft_on_transfer`.** Funding is a plain `ft_transfer` from the owner, as the spec says.
- **No withdraw, upgrade or owner-transfer method.** The spec did not ask for them and each
  is a new way to move money. See risks.

## Risks I know of
1. **Funds can only leave through invoices.** There is no owner withdraw. To recover tokens,
   the owner must add themselves as a payee and approve an invoice, and the agent must pay it,
   inside the daily cap. If the agent key is lost, `set_agent` fixes it; if the owner key is
   lost, nothing can change rules ever again.
2. **The token contract is trusted.** A malicious or buggy token could report success without
   moving funds, or move funds and then fail. The vault believes the receipt outcome.
3. **An agent can retry a failing invoice endlessly** (e.g. receiver not registered with the
   token). Each failed try costs the agent gas and releases its cap reservation; no money moves.
4. **The vault must keep NEAR** for storage (each invoice is stored forever) and the
   1 yoctoNEAR per payment. If it runs out of NEAR, new invoices and payments fail.
5. **The vault must be registered with the token** (`storage_deposit`), and so must each
   receiver, or transfers fail. Failures are recoverable (invoice goes back to `Approved`).
6. **Callback starvation** is guarded by the gas check, but the reserved numbers (20/15 TGas)
   are my estimates, not measurements against a specific token.
7. **Agent compromise** still lets an attacker pay any currently valid invoice early, up to
   the daily cap, to the receiver the owner chose. It cannot redirect money.
8. **Cross-midnight failures**: an amount counted on day D that fails after midnight is not
   credited back to day D (day D is over) and is not subtracted from day D+1. That is safe
   (it never lets more than the cap through) but slightly conservative.
9. **Wasm feature set**: built with Rust 1.86 and no `target-cpu=mvp`. If the target NEAR
   runtime rejects newer wasm features, rebuild with `-C target-cpu=mvp`. I did not deploy it.

# vault-a interface

An invoice vault for an AI agent on NEAR. It holds one NEP-141 token and pays invoices on
behalf of an owner. An AI agent triggers payments.

## Policy (what the owner means)
- Each approved, unexpired, uncancelled invoice authorises **exactly one** transfer of its
  amount to its receiver.
- Cancelled or expired invoices, and invoices whose receiver was removed as a payee,
  authorise nothing.
- Total paid per UTC day is at most `daily_cap`.
- Only the agent can trigger payments. Only the owner can change rules.
- A transfer that genuinely fails leaves the invoice payable again.

Funding: the owner sends tokens to the vault with a plain `ft_transfer` on the token contract.
The vault (and each receiver) must be registered with the token (`storage_deposit`).

## Conventions
- Token amounts are JSON strings of u128, e.g. `"1000000"`.
- `expires_at_ns` is a JSON number: Unix time in nanoseconds (compared with block timestamp).
  An invoice is payable only while block time `<` `expires_at_ns`.
- "1 yocto" means the call must attach exactly 1 yoctoNEAR (`--depositYocto 1`).
- A UTC day is `floor(block_timestamp_ns / 86_400_000_000_000)`.

## Init
| Method | Args | Caller | Returns |
|---|---|---|---|
| `new` | `{"owner": "owner.near", "agent": "agent.near", "token": "token.near", "daily_cap": "1000"}` | the vault account itself only (deploy + init) | — |

`owner` and `agent` must differ.

## Owner methods
| Method | Args | Deposit | Returns |
|---|---|---|---|
| `add_payee` | `{"account": "bob.near"}` | 1 yocto | — |
| `remove_payee` | `{"account": "bob.near"}` | none | — |
| `approve_invoice` | `{"id": "inv-1", "receiver": "bob.near", "amount": "100", "expires_at_ns": 1767225600000000000}` | 1 yocto | — |
| `cancel_invoice` | `{"id": "inv-1"}` | none | — |
| `set_agent` | `{"account": "agent2.near"}` | 1 yocto | — |
| `set_daily_cap` | `{"daily_cap": "5000"}` | 1 yocto | — |

Notes:
- `approve_invoice`: `receiver` must currently be a payee; `id` is 1–64 bytes and can never be
  reused; `amount` > 0; `expires_at_ns` must be in the future.
- `remove_payee`: invoices already approved for that payee become permanently unpayable,
  even if the payee is added again later.
- `cancel_invoice`: fails if the invoice is paid, already cancelled, or has a payment in flight.
- `set_agent`: new agent must differ from the owner.
- `set_daily_cap`: applies immediately, including to the current day.

## Agent method
| Method | Args | Deposit | Gas | Returns |
|---|---|---|---|---|
| `pay` | `{"id": "inv-1"}` | none | at least 50 TGas, 100 TGas recommended | `true` if the transfer succeeded and the invoice is now paid, `false` if the transfer failed and the invoice is payable again |

`pay` fails immediately (no transfer) if: caller is not the agent; invoice unknown, paid,
cancelled, expired, or already being paid; receiver no longer a payee; today's total plus this
amount would exceed `daily_cap`; not enough gas attached.

## Views
| Method | Args | Returns |
|---|---|---|
| `get_invoice` | `{"id": "inv-1"}` | `null` or `{"id", "receiver", "amount": "100", "expires_at_ns": <number>, "status", "payable_now": bool}` |
| `get_config` | `{}` | `{"owner", "agent", "token", "daily_cap": "1000"}` |
| `paid_today` | `{}` | `"150"`: amount paid plus amount in flight during the current UTC day |
| `is_payee` | `{"account": "bob.near"}` | `bool` |

`status` is one of `Approved`, `Pending` (payment in flight), `Paid`, `Cancelled`,
`Expired`, `PayeeRemoved`.

## Events
Each state change logs a line `EVENT_JSON:{"standard":"vault-a","version":"1.0.0","event":...,"data":[...]}`
with event names `payee_added`, `payee_removed`, `invoice_approved`, `invoice_cancelled`,
`agent_set`, `daily_cap_set`, `payment_started`, `payment_succeeded`, `payment_failed`.

//! vault-a: an invoice vault for an AI agent on NEAR.
//!
//! The vault holds one NEP-141 token. The owner approves invoices
//! (receiver + amount + expiry). The agent triggers payment of an approved
//! invoice. Each invoice can move its amount to its receiver exactly once.
//! See DESIGN.md for the state machine and the reasoning behind each check.

use near_sdk::json_types::U128;
use near_sdk::store::LookupMap;
use near_sdk::{
    assert_one_yocto, env, log, near, require, serde_json, AccountId, BorshStorageKey, Gas,
    NearToken, PanicOnDefault, Promise, PromiseError,
};

/// Nanoseconds in one UTC day. NEAR block timestamps are Unix-epoch ns,
/// so `timestamp / NS_PER_DAY` is the UTC day number.
const NS_PER_DAY: u64 = 86_400 * 1_000_000_000;

/// Gas handed to the token's `ft_transfer`.
const GAS_FT_TRANSFER: Gas = Gas::from_tgas(20);
/// Gas reserved for our own callback. The callback must never run out of gas,
/// otherwise the invoice would be stuck in `Pending`.
const GAS_CALLBACK: Gas = Gas::from_tgas(15);
/// Gas we need left for the rest of `pay` itself after scheduling.
const GAS_PAY_OVERHEAD: Gas = Gas::from_tgas(10);

const MAX_ID_LEN: usize = 64;

#[derive(BorshStorageKey)]
#[near]
enum StorageKey {
    Payees,
    Invoices,
}

#[near(serializers = [borsh, json])]
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum InvoiceStatus {
    /// Approved by the owner; can be paid if unexpired and receiver still a payee.
    Approved,
    /// A transfer is in flight; waiting for the callback.
    Pending,
    /// Transfer succeeded. Terminal.
    Paid,
    /// Cancelled by the owner. Terminal.
    Cancelled,
}

#[near(serializers = [borsh])]
#[derive(Clone, Debug)]
pub struct Invoice {
    pub receiver: AccountId,
    pub amount: u128,
    pub expires_at_ns: u64,
    pub status: InvoiceStatus,
    /// Payee "generation" the receiver had when the invoice was approved.
    /// Removing a payee and adding it back gives it a new generation, so
    /// invoices approved before the removal stay dead.
    pub payee_generation: u64,
    /// UTC day the in-flight amount was counted against (only while Pending).
    pub pending_day: Option<u64>,
}

#[near(serializers = [json])]
pub struct InvoiceView {
    pub id: String,
    pub receiver: AccountId,
    pub amount: U128,
    pub expires_at_ns: u64,
    /// One of "Approved", "Pending", "Paid", "Cancelled", "Expired", "PayeeRemoved".
    /// "Expired" and "PayeeRemoved" are derived: the stored status is Approved
    /// but the invoice can no longer be paid.
    pub status: String,
    pub payable_now: bool,
}

#[near(serializers = [json])]
pub struct ConfigView {
    pub owner: AccountId,
    pub agent: AccountId,
    pub token: AccountId,
    pub daily_cap: U128,
}

#[near(contract_state)]
#[derive(PanicOnDefault)]
pub struct VaultA {
    owner: AccountId,
    agent: AccountId,
    token: AccountId,
    daily_cap: u128,
    /// payee -> generation number.
    payees: LookupMap<AccountId, u64>,
    next_payee_generation: u64,
    invoices: LookupMap<String, Invoice>,
    /// UTC day number that `spent_amount` refers to.
    spent_day: u64,
    /// Amount paid or in flight during `spent_day`.
    spent_amount: u128,
}

fn current_day() -> u64 {
    env::block_timestamp() / NS_PER_DAY
}

fn emit(event: &str, data: serde_json::Value) {
    log!(
        "EVENT_JSON:{}",
        serde_json::json!({"standard": "vault-a", "version": "1.0.0", "event": event, "data": [data]})
    );
}

#[near]
impl VaultA {
    /// Only the vault account itself may initialise (deploy + init in one
    /// transaction), so nobody can front-run initialisation with their own owner.
    #[init]
    #[private]
    pub fn new(owner: AccountId, agent: AccountId, token: AccountId, daily_cap: U128) -> Self {
        require!(owner != agent, "owner and agent must be different accounts");
        require!(
            agent != env::current_account_id() && owner != env::current_account_id(),
            "owner/agent cannot be the vault itself"
        );
        require!(token != env::current_account_id(), "token cannot be the vault itself");
        Self {
            owner,
            agent,
            token,
            daily_cap: daily_cap.0,
            payees: LookupMap::new(StorageKey::Payees),
            next_payee_generation: 1,
            invoices: LookupMap::new(StorageKey::Invoices),
            spent_day: current_day(),
            spent_amount: 0,
        }
    }

    // ------------------------------------------------------------------
    // Owner methods
    // ------------------------------------------------------------------

    /// Add a payee. Requires exactly 1 yoctoNEAR (full-access key).
    /// Re-adding an existing payee is a no-op (keeps its generation).
    #[payable]
    pub fn add_payee(&mut self, account: AccountId) {
        assert_one_yocto();
        self.assert_owner();
        require!(account != env::current_account_id(), "vault cannot be a payee");
        if self.payees.contains_key(&account) {
            return;
        }
        let generation = self.next_payee_generation;
        self.next_payee_generation += 1;
        self.payees.insert(account.clone(), generation);
        emit("payee_added", serde_json::json!({"account": account}));
    }

    /// Remove a payee. All invoices approved for this payee become permanently
    /// unpayable, even if the payee is added again later. No deposit needed
    /// (restricting is always safe, so it should be easy in an emergency).
    pub fn remove_payee(&mut self, account: AccountId) {
        self.assert_owner();
        if self.payees.remove(&account).is_some() {
            emit("payee_removed", serde_json::json!({"account": account}));
        }
    }

    /// Approve a new invoice. Requires exactly 1 yoctoNEAR.
    #[payable]
    pub fn approve_invoice(
        &mut self,
        id: String,
        receiver: AccountId,
        amount: U128,
        expires_at_ns: u64,
    ) {
        assert_one_yocto();
        self.assert_owner();
        require!(!id.is_empty() && id.len() <= MAX_ID_LEN, "invoice id must be 1..=64 bytes");
        require!(!self.invoices.contains_key(&id), "invoice id already used");
        require!(amount.0 > 0, "amount must be positive");
        require!(expires_at_ns > env::block_timestamp(), "expiry must be in the future");
        let generation = match self.payees.get(&receiver) {
            Some(g) => *g,
            None => env::panic_str("receiver is not a payee"),
        };
        self.invoices.insert(
            id.clone(),
            Invoice {
                receiver: receiver.clone(),
                amount: amount.0,
                expires_at_ns,
                status: InvoiceStatus::Approved,
                payee_generation: generation,
                pending_day: None,
            },
        );
        emit(
            "invoice_approved",
            serde_json::json!({"id": id, "receiver": receiver, "amount": amount, "expires_at_ns": expires_at_ns.to_string()}),
        );
    }

    /// Cancel an approved invoice. Fails if the invoice is already paid,
    /// already cancelled, or has a transfer in flight (an in-flight transfer
    /// cannot be recalled; wait for its outcome and cancel if it failed).
    pub fn cancel_invoice(&mut self, id: String) {
        self.assert_owner();
        let inv = match self.invoices.get_mut(&id) {
            Some(inv) => inv,
            None => env::panic_str("invoice not found"),
        };
        match inv.status {
            InvoiceStatus::Approved => inv.status = InvoiceStatus::Cancelled,
            InvoiceStatus::Pending => env::panic_str("transfer in flight; cannot cancel now"),
            InvoiceStatus::Paid => env::panic_str("invoice already paid"),
            InvoiceStatus::Cancelled => env::panic_str("invoice already cancelled"),
        }
        emit("invoice_cancelled", serde_json::json!({"id": id}));
    }

    /// Replace the agent. Requires exactly 1 yoctoNEAR.
    #[payable]
    pub fn set_agent(&mut self, account: AccountId) {
        assert_one_yocto();
        self.assert_owner();
        require!(account != self.owner, "owner and agent must be different accounts");
        require!(account != env::current_account_id(), "agent cannot be the vault itself");
        self.agent = account.clone();
        emit("agent_set", serde_json::json!({"agent": account}));
    }

    /// Change the daily cap. Takes effect immediately, including for today:
    /// if today's spend already exceeds the new cap, no more payments today.
    /// Requires exactly 1 yoctoNEAR.
    #[payable]
    pub fn set_daily_cap(&mut self, daily_cap: U128) {
        assert_one_yocto();
        self.assert_owner();
        self.daily_cap = daily_cap.0;
        emit("daily_cap_set", serde_json::json!({"daily_cap": daily_cap}));
    }

    // ------------------------------------------------------------------
    // Agent method
    // ------------------------------------------------------------------

    /// Pay an approved invoice. Agent only. Attach at least ~50 TGas
    /// (100 TGas recommended). No deposit.
    pub fn pay(&mut self, id: String) -> Promise {
        require!(env::predecessor_account_id() == self.agent, "only the agent can pay");

        // The callback must be guaranteed enough gas, or the invoice could be
        // left stuck in Pending. Check before touching state.
        let needed = GAS_FT_TRANSFER
            .saturating_add(GAS_CALLBACK)
            .saturating_add(GAS_PAY_OVERHEAD);
        let remaining = env::prepaid_gas().saturating_sub(env::used_gas());
        require!(remaining >= needed, "not enough gas attached to pay safely");

        let now = env::block_timestamp();
        let today = now / NS_PER_DAY;

        let (receiver, amount) = {
            let inv = match self.invoices.get(&id) {
                Some(inv) => inv,
                None => env::panic_str("invoice not found"),
            };
            match inv.status {
                InvoiceStatus::Approved => {}
                InvoiceStatus::Pending => env::panic_str("payment already in flight"),
                InvoiceStatus::Paid => env::panic_str("invoice already paid"),
                InvoiceStatus::Cancelled => env::panic_str("invoice cancelled"),
            }
            require!(now < inv.expires_at_ns, "invoice expired");
            match self.payees.get(&inv.receiver) {
                Some(g) if *g == inv.payee_generation => {}
                _ => env::panic_str("receiver is no longer a payee"),
            }
            (inv.receiver.clone(), inv.amount)
        };

        // Daily cap: roll the window if the UTC day changed, then reserve.
        self.roll_day(today);
        let new_spent = match self.spent_amount.checked_add(amount) {
            Some(v) => v,
            None => env::panic_str("daily cap exceeded"),
        };
        require!(new_spent <= self.daily_cap, "daily cap exceeded");
        self.spent_amount = new_spent;

        // Mark in flight BEFORE scheduling the transfer, so a second `pay`
        // in a later block cannot start another transfer for the same invoice.
        {
            let inv = self.invoices.get_mut(&id).expect("checked above");
            inv.status = InvoiceStatus::Pending;
            inv.pending_day = Some(today);
        }

        emit(
            "payment_started",
            serde_json::json!({"id": id, "receiver": receiver, "amount": U128(amount)}),
        );

        let args = serde_json::json!({
            "receiver_id": receiver,
            "amount": U128(amount),
            "memo": format!("vault-a invoice {}", id),
        });

        Promise::new(self.token.clone())
            .function_call(
                "ft_transfer".to_string(),
                serde_json::to_vec(&args).expect("serialize args"),
                NearToken::from_yoctonear(1),
                GAS_FT_TRANSFER,
            )
            .then(
                Self::ext(env::current_account_id())
                    .with_static_gas(GAS_CALLBACK)
                    .on_transfer_complete(id),
            )
    }

    /// Callback after `ft_transfer`. Only callable by the vault itself.
    /// Returns true if the invoice is now Paid. Written so it does not panic:
    /// a panic here would leave the invoice stuck in Pending.
    #[private]
    pub fn on_transfer_complete(&mut self, id: String) -> bool {
        // NEP-141 ft_transfer returns nothing and panics on any failure, so
        // "the receipt succeeded" is the outcome. We read at most 0 bytes of
        // the return value; a non-empty return (TooLong) still means success.
        let succeeded = env::promise_results_count() == 1
            && match env::promise_result_checked(0, 0) {
                Ok(_) => true,
                Err(PromiseError::TooLong(_)) => true,
                Err(_) => false,
            };

        let (amount, pending_day) = match self.invoices.get_mut(&id) {
            Some(inv) if inv.status == InvoiceStatus::Pending => {
                let day = inv.pending_day.take();
                if succeeded {
                    inv.status = InvoiceStatus::Paid;
                } else {
                    inv.status = InvoiceStatus::Approved;
                }
                (inv.amount, day)
            }
            _ => {
                // Should be unreachable: only `pay` schedules this callback and
                // it always sets Pending first. Log and do nothing.
                log!("vault-a: callback for invoice {} not in Pending state; ignored", id);
                return false;
            }
        };

        if succeeded {
            emit("payment_succeeded", serde_json::json!({"id": id, "amount": U128(amount)}));
            true
        } else {
            // Release the reservation, but only from the day it was counted
            // against. If the window has since rolled to a new day, the old
            // day's counter no longer exists and there is nothing to release.
            if pending_day == Some(self.spent_day) {
                self.spent_amount = self.spent_amount.saturating_sub(amount);
            }
            emit("payment_failed", serde_json::json!({"id": id, "amount": U128(amount)}));
            false
        }
    }

    // ------------------------------------------------------------------
    // Views
    // ------------------------------------------------------------------

    pub fn get_invoice(&self, id: String) -> Option<InvoiceView> {
        let inv = self.invoices.get(&id)?;
        let now = env::block_timestamp();
        let payee_ok = matches!(self.payees.get(&inv.receiver), Some(g) if *g == inv.payee_generation);
        let (status, payable_now) = match inv.status {
            InvoiceStatus::Approved if now >= inv.expires_at_ns => ("Expired", false),
            InvoiceStatus::Approved if !payee_ok => ("PayeeRemoved", false),
            InvoiceStatus::Approved => ("Approved", true),
            InvoiceStatus::Pending => ("Pending", false),
            InvoiceStatus::Paid => ("Paid", false),
            InvoiceStatus::Cancelled => ("Cancelled", false),
        };
        Some(InvoiceView {
            id,
            receiver: inv.receiver.clone(),
            amount: U128(inv.amount),
            expires_at_ns: inv.expires_at_ns,
            status: status.to_string(),
            payable_now,
        })
    }

    pub fn get_config(&self) -> ConfigView {
        ConfigView {
            owner: self.owner.clone(),
            agent: self.agent.clone(),
            token: self.token.clone(),
            daily_cap: U128(self.daily_cap),
        }
    }

    /// Amount paid plus amount in flight during the current UTC day.
    pub fn paid_today(&self) -> U128 {
        if self.spent_day == current_day() {
            U128(self.spent_amount)
        } else {
            U128(0)
        }
    }

    pub fn is_payee(&self, account: AccountId) -> bool {
        self.payees.contains_key(&account)
    }

    // ------------------------------------------------------------------
    // Internal
    // ------------------------------------------------------------------

    fn assert_owner(&self) {
        require!(env::predecessor_account_id() == self.owner, "only the owner can do this");
    }

    fn roll_day(&mut self, today: u64) {
        if today != self.spent_day {
            self.spent_day = today;
            self.spent_amount = 0;
        }
    }
}
