## A bug I found in my own step-2 change, and the re-run

The **first** verify run (also 43 of 43) printed, on the control's `07-outsider-pays`:
`NON-AGENT PAY: outsider started a transfer for inv-pay`. The same log shows that call was **refused**
("only the agent can pay"), and nothing moved. So the message said the opposite of what happened.

Cause: `harness/src/seq.rs` judged "pay succeeded" from the transaction's outcome, which succeeds even
when the guard then panics. Fixed to read the pay call's own receipt. The same gate also fed the older
expiry timestamp, so a refused pay before expiry could have stood in for a real pay after expiry. Neither
moved a number in any run here; details in the fix plan ("Step 3 interruption"). After the fix, the whole
of verify was re-run; this file reports the re-run. No `NON-AGENT PAY` line appears in it (every outsider
call was refused). First run kept as `verify-2026-11-11-run1-console.log` and
`arena-2026-11-11-positive-control-run1.log`.
